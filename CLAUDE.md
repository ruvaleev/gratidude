# gratidude

Дневник благодарностей и похвал себе. Данные живут только на устройстве — бэкенда, аккаунтов и сети в проекте нет.

## Правила работы

1. **Инструкции фиксировать сразу.** Как только пользователь сформулировал правило или решение — записать его в этот файл в том же ответе, до продолжения кода. Не «запомнить на сессию».
2. **Делать ровно то, о чём попросили.** Не добавлять тумблеры, секции и опции «на всякий случай». Если чего-то не хватает — сказать одной строкой и сделать по запросу.
3. **Не поднимать dev-сервер без просьбы.** Проверка — `tsc`, `eslint`, `jest`, а не скриншоты в браузере.
4. **Не переписывать согласованное.** Если раздел утверждён — правится только названная часть.

## Package Manager

Use `yarn` for all commands. NOT npm/npx.

## Tech Stack

- React Native 0.81 + Expo ~54, React 19
- **expo-router 6** (file-based routing в `app/`). `@react-navigation/*` тянется им как зависимость — напрямую конфиги навигации не пишем
- Redux Toolkit (slices pattern) + react-redux + **redux-persist** поверх AsyncStorage
- i18next + react-i18next, язык устройства через expo-localization
- **react-native-svg** — весь рендер клумбы; react-native-reanimated для анимаций
- Jest + @testing-library/react-native
- Сети нет: ни Axios, ни Firebase, ни API-слоя. Экспорт/бэкап — локальные файлы через expo-file-system + expo-sharing

## Testing

- Прогнать всё: `yarn test`
- Точечно: `yarn test <path>`
- **Jest подхватывает только `**.test.tsx`** (см. `testMatch` в package.json) — тест в `.ts` просто не запустится
- Тесты лежат в `__tests__/`, зеркалят структуру проекта; хелперы (`renderWithProviders`, `createStore`, `entry`, `setPlatform`) — в `__tests__/utils/index.tsx`, глобальные моки (AsyncStorage, expo-router, expo-localization, expo-sharing, vector-icons) — в `__tests__/jest-setup.js`
- Coverage по умолчанию выключено, `--no-coverage` не нужен
- Линтер: `yarn lint` (expo lint) или точечно `yarn eslint <path>`
- Типы: `yarn tsc --noEmit`

## Project Structure

Плоская структура, **`src/` нет**. Алиас `@/*` указывает в корень.

- `app/` — экраны expo-router. **Все** экраны лежат в группе `(tabs)`: `index|week|month` плюс `settings` и `playground` с `href: null` (в таб-баре кнопки нет, роут доступен по ссылке). Корневой `Stack` в `app/_layout.tsx` держит только группу и не рисует хедеров
- `components/` — переиспользуемые UI-компоненты; `components/settings/setting-row.tsx` — общие строки настроек (`SettingsSection`, `ToggleRow`, `StepperRow`)
- `garden/` — модуль клумбы, изолирован от остального UI: `config.ts` (пропорции, лимиты, палитра растений), `scene.ts` (чистая сборка сцены из записей дня), `random.ts` (сид от даты — день всегда выглядит одинаково), `components/`, `useGardenScene.ts`
- `store/` — RTK: `slices/`, `selectors/`, `index.ts` (persist + версия данных), `types.ts`
- `constants/theme.ts` — токены интерфейса (цвета, отступы). Палитра клумбы живёт отдельно в `garden/config.ts` — **смешивать нельзя**
- `hooks/`, `utils/`, `locales/` (`en.json`, `ru.json`), `i18n.ts`
- `app-example/` — остатки шаблона Expo, исключены из lint/tsc/тестов. Не трогать
- `suggested_designs/`, `notes/` — черновики дизайна и заметки, не код приложения

## Соглашения

- Тексты интерфейса — только через i18next (`locales/en.json` + `locales/ru.json`), хардкод строк недопустим. Исключение — `app/playground.tsx`, он намеренно не локализован
- Цвета и отступы — только из `constants/theme.ts`, литералы в стилях не писать
- Даты в сторе и в сцене — формат `DD.MM.YYYY`, он же служит зерном раскладки клумбы
- `eslint.config.js` требует точки с запятой (`semi: always`)

## Согласованные решения по UI

### Навигация — на всех экранах

Обе панели принадлежат `app/(tabs)/_layout.tsx`, а не экранам: `<Header/>` (полоса вдохновения + шестерёнка) стоит над `<Tabs>`, таб-бар — под ним. Поэтому:
- новый экран добавляется **внутрь** `app/(tabs)/`, иначе он останется без навигации;
- если кнопка в таб-баре не нужна — `<Tabs.Screen name="..." options={{ href: null }} />`;
- экран **не** оборачивает себя в `SafeAreaView` — верхний отступ даёт layout, нижний закрывает таб-бар. Внутри экрана — обычный `View`;
- экран не рендерит `<Header/>` сам;
- экраны вне таб-бара (`settings`, `playground`) ставят первым элементом `<ScreenTitle title={...} />` — он даёт заголовок и стрелку назад вместо снятого нативного хедера.

### `app/(tabs)/playground.tsx` (песочница клумбы, доступна из настроек)

Экран локализован наравне с остальным приложением (`playground.*` в локалях). Состояние ручек живёт в `store/slices/playgroundSlice.ts` — не в `useState`. В persist-whitelist слайс намеренно не входит.

Секция **«Пресеты»** — два блока-трека, «Похвалы себе» (praises) и «Благодарности» (gratitudes). В каждом:
- ряд чипов-пресетов (Пусто / Скудный / Обычный / Цель взята / Перебор), активный подсвечен; ручная правка любой ручки снимает подсветку;
- степпер «Записей за день»;
- сегмент «Баллы за запись» — **внутри трека**, не отдельной секцией. У похвал в нём четыре чипа (выкл / все 1 / вперемешку / все 3), у благодарностей три: `points.enabled` в `scene.ts` влияет только на стадию растений, то есть только на трек похвал.

Тумблеров в песочнице нет: и «Баллы за запись», и «Трек благодарностей» убраны — ненужный трек просто оставляют пустым, а баллы выключаются чипом «выкл». Оба трека всегда включены.

По умолчанию `pointsEnabled: false` — как в `settingsSlice`. Это важно: при включённых баллах стадия растения зависит **только** от баллов своей записи, поэтому 14 записей по 1 баллу дают 12 ростков, а не 12 цветов. Подсказка под секцией меняется вместе с режимом и объясняет это.

Секция **«Цветок месяца»** показывает все 12 сезонных цветков из `SEASON_FLOWERS` плашками с их настоящими цветами лепестков; выбор плашки задаёт месяц. Отдельная секция **«Раскладка»** — степпер дня месяца (дата = зерно расстановки).
